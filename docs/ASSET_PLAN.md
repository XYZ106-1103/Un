# UNCLAIMED — 에셋 제작 및 관리 계획

> 문서 버전 0.2 (v0.1.0) · 현재 상태는 `npm run assets:report`로 확인합니다.

## 1. 원칙

1. **모든 에셋은 `src/data/assets/manifest.json`에 등록합니다.** 등록되지 않은 이미지는 로드되지 않습니다.
2. **상태를 숨기지 않습니다.**
   - `placeholder` — 생성된 대체물. 반드시 교체. 화면에는 **마젠타색 X 박스 / 마젠타 실루엣**으로 그려지고, 해당 화면 구석에 "임시 아트: …" 표시가 붙습니다.
   - `wip` — 실제 아트, 다듬는 중.
   - `final` — 승인됨.
3. 파일이 없거나 로드에 실패해도 게임은 멈추지 않습니다. 자동으로 플레이스홀더가 쓰이고 콘솔에 오류가 남습니다.
4. 출시 빌드 전 `npm run assets:report -- --strict`가 통과해야 합니다(플레이스홀더 0개).
5. 모든 아트·음악·효과음은 이 프로젝트를 위해 새로 만든 것만 씁니다.

### 2.1 캐릭터 애니메이션 목록

필수(모든 대화 캐릭터): 대기(2–4f), 걷기 4방향(4f), 말하기 입 모양(2f).
감정(이야기에 필요한 캐릭터만): 놀람, 웃음, 슬픔, 분노, 고유 특수 행동 1개 이상.
전투 적: 대기(루프), 피격(1–2f), 놓아주기 반응, 고유 공격 동작.

### 2.2 제작 파이프라인

```
Aseprite (.aseprite, 레이어·태그 = 애니메이션 이름)
  └─ 내보내기: PNG 시트 + JSON (Array, frame tags 포함)
       └─ src/assets/sprites/<category>/<name>.png (+ .json)
            └─ manifest.json 항목의 file 경로 지정, status 갱신
```

- 아주 작은 스프라이트(영혼, 탄, 커서, 아이콘)는 manifest에 `kind: "pixels"`로 **팔레트 인덱스 문자열**을 직접 작성할 수 있습니다(diff로 리뷰 가능). 예: `soul.tag`.
- 파일명: `kebab-case`. 키: `category.name` (예: `char.mitt`, `bg.sorting-room`, `ui.dialogue-frame`).
- 원본 `.aseprite` 파일은 `art-src/`(추후 생성, Git LFS 권장)에 보관합니다.

### 4.1 wip → final 절차

1. 실제 게임 화면(1배·4배)에서 확인, 팔레트 외 색·고립 픽셀·반투명 없음
2. 애니메이션은 실제 재생 속도로 확인
3. manifest의 `status`를 `final`로 변경, 커밋 메시지에 검수 사항 기록
